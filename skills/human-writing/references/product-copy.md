# Product Copy

Write for someone using the interface to accomplish a task. Use the surrounding screen and interaction state as context.

- Use the product's established names for actions and objects. A clever synonym can make the same concept look like two different things.
- Make action labels predict the result. Distinguish actions with materially different consequences, such as saving a draft and publishing it.
- Explain a prerequisite before the user needs it. Put field-specific guidance beside the field instead of making people remember a paragraph elsewhere.
- For errors, say what happened and how to recover when a recovery path is known. Say whether entered work was saved only when the interface behaviour confirms it.
- For confirmations and status messages, state the actual state. Do not report success while an operation is still pending.
- For empty states, distinguish no data yet, no matching results, and unavailable data. Offer the next useful action when one exists.
- Keep essential conditions and consequences visible near the decision. Do not hide them in a tooltip or remove them merely to shorten the text.
- Prefer neutral clarity during errors, payment, consent, and destructive actions. Avoid jokes or reassurance that minimise the user's situation.

## Example

Unhelpful error: “Oops! Something went wrong.”

If verified by the interface behaviour: “The upload stopped because the file is over 20 MB. Choose a smaller file and try again.”

Before returning, read the copy in its interface state: can the user tell what is happening, what an action will do, and how to proceed without guessing?
